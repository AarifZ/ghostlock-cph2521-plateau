## Where we are in one paragraph
The full exploit chain is **proven end-to-end up to the fops swap surviving on
device**. The SLIDE oracle leaks the exact KASLR slide (arithmetic verified
against the stock Image), the SLIDE_SWAP walk lands the fops swap through the
P0 physmap alias, and with the staged clone table the device **SURVIVES with
the swap live** (N3, N5 = CLASS ALIVE — first time ever). The remaining work is
purely operational: run `swap_probe` (already written + on device) in the
~2-minute window after a surviving swap to exercise the configfs write
primitive, repair llseek, arm read, overwrite modprobe_path, and trigger it.
Two windows were lost to timing/disconnects (N3, N5) — not to a technical
blocker.

## Answer to "did we get selinux permissive?"
**No.** SELinux stayed enforcing. We never exercised the write primitive on a
live swap. `mp` (the modprobe script) writes `0 > /sys/fs/selinux/enforce`
when it runs as root — that is the moment SELinux goes permissive.

## Proven facts (all device-verified this session)
1. **Slide decode is exact**: stock Image `nfulnl_logger+0` static =
   0xFFFFFFC00A071F66 = `expected_name` constant. Boot-id UUID bytes 0-7 =
   runtime slid ptr; slide = name - expected_name. Decoded cleanly on 9+ boots
   (0x1F0AE00000, 0x24AEE00000, 0x17AAA00000, 0x256FC00000, 0x11F2C00000,
   0x25D0800000, 0x171D600000, 0x175FC00000, 0x2DD2800000, 0x1ECC400000...).
2. **UUID tail = change_child side effect**: `*(tree_pc+0x08) = tree_l`
   executes unconditionally in the erase (else-branch of __rb_change_child
   writes without matching). Tail 0xFFFFFF802A8DA8E0 = P0(0x28DA8E0) is our own
   write target reflected back, NOT a signature. Consequence: **the swap always
   clobbers fake_fops+0x08 (llseek slot) with the MISC.fops slot address**.
3. **Slot map from real Image table** (ashmem_fops @ image 0x22BFDC8):
   llseek+0x08, read_iter+0x20, ioctl+0x50, compat+0x58, mmap+0x60,
   open+0x70, release+0x80. target.h FIRST macro block is correct for 5.10.
   Real ioctl=0x1837928, compat=0x1837930, mmap=0x1822A68, open=0x1831488,
   release=0x1831490, llseek=0x181FEF8, read_iter=0x1822948,
   noop_llseek=0x181FE48, cfg_read=0x182FCF8, cfg_write=0x01830218.
4. **5.10 vfs prefers .read/.write over _iter** — putting configfs read JT in
   .read exposed system reads → 3 deaths (SS1/R2/W1). Fixed by staged table.
5. **Staged clone table survives**: bit-exact ashmem clone + ONLY .write armed
   (+0x18 = cfg_write JT). read=NULL → system reads go to real read_iter.
   N3/N5 ALIVE proves system traffic is safe through it.
6. **Delayed death (~2 min) = llseek clobber** (fact 2): some process
   eventually llseeks an ashmem fd → jumps to data addr → panic. Fix = repair
   llseek via the write primitive immediately after swap (swap_probe step 2).
7. **Walk reliability**: fresh-process single walk ≈ 45-55%. Second walk
   in-process = 0/5 (never worked — kernelsnitch/slab degradation). Two-fire
   strategy (oracle fire → swap fire) is the proven pattern.
8. **Fops owner=1 kills instantly**: rb_leaf shell +0x00=1 →
   try_module_get((struct module*)1) fault at first open (SS1/R2 analysis).
   Attack/clone tables use owner=0.
9. **adb-blip false SOFTBOOTs**: classifier sometimes says SOFTBOOT when the
     boot survived (fork storm disturbs adbd). ALWAYS verify with
   boot_id + uptime continuity before re-firing.
10. modprobe_path = image 0x27E0F78 (kallsyms D symbol). KIMAGE_TEXT_BASE =
    0xffffffc080000000.
